# 顕在意識の動機・履歴・行動接続 基本設計 第2版

日付: 2026-10-06。対象: 顕在意識の入力・状態更新・行動選択。状態: 第1版の独立レビューを反映した基本設計候補。実装・配備・有料試験は未着手。

## 1. 今回の課題と所有者の方向

課題は、相手へ働きかける動機が弱く、姿勢表明や待機が続く可能性である。所有者は、目的 → 現在の状態・潜在の感情や衝動 → 目的のための意思 → 行動という流れを提案した。状態を分かるラベルで保持し、差分と行動選択を同じ呼び出しで返す。研究理論を長く説明するプロンプトではなく、一行の意味説明を使う。過去のセリフとその時の状況の履歴も必要と指摘した。

今回の依頼は、この方向を設計に起こし、独立レビューで「課題に対する効果的な次の手か、よりよい手があるか」を確認して進めること。細かな実装指摘をレビューの主目的にしない。

目的はプレイヤーが、人物の目的と状況から働きかけが生まれ、相手の返答や出来事によって意思・行動が発展する試合を読めることである。単に行動種類や文章表現を増やすことは達成条件にしない。目的ある反復、待機、沈黙、撤退も認める。

## 2. 観測、仮説、既存契約

- 観測: rc17公開試合は潜在48回、顕在13回、実況25回、裁定9回。顕在の平均入力は約4,688トークン。総SDK試行96回は完了したが、それだけで裁定や人物表現の品質を証明しない。
- 観測: `AwarenessConsciousStateSchema` はgoal・thought・updatedTick、入力は人物資料・知覚・feltProjection・受理済み意識状態・facts・availableActions。セリフと当時の状況の明示的な履歴欄はない。出力はgoal・thought・desires・influences。
- 観測: `awareness-request.ts` は明確な思考と意欲を求めるが、目的から現在の欲求・意思への接続を分けて保持していない。
- 仮説: 目的と現在の働きかけの結びつき、相手との未解決のやり取りが入力・状態として弱く、同じ姿勢の表明を再生成しやすい。
- 未確認: 動機の薄さが単調化の主原因か。試合には自由行動の裁定未確定もあり、選んだ行動が成立しないことによる停滞を、本案だけで解消したとは扱わない。

既存の正準世界と本人の知覚の区別、潜在の低顕在度、潜在と顕在の並行実行、強度による意欲競合、非同期jobのgeneration/fence、現在世界での実行判定、実利用トークン記録を保持する。根拠はAccepted ADR0051が継承するADR0050のパイプラインと、ADR0056の最新版指示契約である。

## 3. 基本設計の方針

持続する人物の軸と目的、本人が捉えた現在状況、潜在から自覚できる感じ、本人が経験したやり取りを、短い自然文として一度の顕在呼び出しへ渡す。同じ呼び出しで意識状態の差分と具体的な行動意欲・発声・潜在への働きかけを返す。

目的が、相手や環境のどの状態を変えたいかという欲求を生み、そのために何をしようと決めるかという意思へつながる。これは説明用の構成であり、毎回四段階の長い推論文や全項目更新を要求しない。感情は目的への評価に影響し、意思によって受け止め方も変わり得る。反射・衝動は別の潜在経路で引き続き行動を促す。

## 4. 顕在入力

| 節 | 渡す内容 | 経済性と知覚の境界 |
|---|---|---|
| 人物の軸 | 価値観・性格・判断の癖・今回に必要な背景、話し方 | キャラの不変資料に根拠を持つ短い投影。存在しない使命・関係・危機を創作しない |
| 今の意識 | 目的・状況認識・欲求・意思の現在値 | 持続する意味を保持。目的の毎回再生成や全文思考の累積をしない |
| 今回の知覚 | 自他の行動・身体感覚・相手の発言・環境について本人が認識した情報 | 世界の全知情報を送らず、分からないことと帰属不明を残す |
| 内側の感じ | feltProjection相当の感情・衝動・短い直感 | 低顕在度の原因を説明せず、曖昧さを保持する |
| 直近の経験 | セリフ原文とその時の知覚状況、本人の行動と知覚した結果 | 同じ情報を今回の知覚と履歴の両方に全文再掲しない |
| 残っていること | 約束・要求・拒絶・未回答の問い・未解決の出来事 | 本人に根拠があるものだけ。相手が同意した等を推測しない |
| 選べる行動 | 現在の合法候補・参照と判断に必要な能力条件 | 候補IDの対応と適用条件を保持。複雑な行動を潜在へ流さない |

人物の軸は潜在用の反応傾向と同じ圧縮ではない。顕在には目的を理解する背景が必要な場合がある。初回は人物と遭遇状況から目的を持てる材料を渡すが、特定の対人目標や攻撃を機械側が一律に設定しない。

### 履歴の形

各経験は、時点・出来事参照・本人が知覚した状況・セリフの原文と話者・知覚した結果を結びつける。観測した事実と本人の解釈は区別する。認識がない相手の発言や、公開実況を本人の経験として逆流させない。

直近の経験は原文を保つ短い窓、以前から残る事項は根拠参照を持つ要点とする。重要な原文が必要ならその引用を残す。窓から外れたことだけを理由に、まだ有効な約束や要求を消さない。初回や履歴がない場合には空として扱い、架空の経験を埋めない。

追加LLMによる毎回の要約はしない。既存の知覚・発言・確定した自分の行動記録から機械的に窓を構築し、残る事項は同じ顕在応答で更新する案とする。窓の件数・文字数、重要事項の型と失効は詳細設計で決める。入力全体が短くなるとは未測定の段階で断定しない。

## 5. ラベルと差分出力

| ラベル | LLMへ渡す一行説明 |
|---|---|
| 目的 | 継続して実現したいこと |
| 状況認識 | 今、自分はどういう状況だと思っているか |
| 欲求 | 今、何を変えたいか |
| 意思 | そのために、何をしようと決めたか |

状態は省略なら維持、値なら置換、明示的な解除なら終了とする。目的も変化し得るが、毎回言い直すためには更新しない。目標未設定の初回、目的達成・断念、欲求と意思の解除を表現できるようにする。意味上のルールであり、下の例をそのまま正式wire型としない。

```json
{
  "更新": {
    "欲求": "相手を仲間から遠ざけたい",
    "意思": "間に入り、進路を塞ぐ"
  },
  "行動意欲": {
    "行動候補": "提示された候補ID",
    "強さ": 0.8
  }
}
```

意欲は同じ応答で返す。状態更新がなくても現在の意思を遂行する行動は選べる。発声も意思を実現する行動の一つとして既存のvoice経路へ渡す。行動の成功や相手の反応を出力で確定しない。潜在への働きかけは既存influencesを保持し、感情状態を直接書き換えない。

自由な思考本文は長い推論の代わりに各状態へ意味を保持する方向。ただし既存thoughtの廃止・保存形式の変更は正式な出力契約の改訂に属する。思考材料を全て捨てることや、LLM内部推論設定を変更することを本案に含めない。

## 6. 短いプロンプトと入出力例

説明候補:

> この人物として、目的・今の状況・感じ・これまでのやり取りを受けて、今の欲求と意思を考えてください。状態は変わった項目だけ返し、それに沿う行動と必要な発言を選んでください。本人が知らないことや、実行の成功を決めないでください。

入力例（架空の設計例であり現在試合の事実ではない）:

> 人物の軸: 仲間を大切にする。慎重だが、仲間への危険には踏み込む。  
> 目的: 仲間を守る。欲求: 相手を遠ざける。意思: 声をかけて自分へ注意を向ける。  
> 直近の経験: 自分「そこから離れろ」。相手は仲間のそばで「お前には関係ない」と返した。  
> 今回: 相手はこちらを見ず、仲間へ一歩近づいた。  
> 内側の感じ: 怖い。胸がざわつく。でも放っておけない。  
> 候補: 合法な接近・進路への移動・発声・待機等の、現在条件を伴う提示。

期待する意味: 「呼びかけで止まらなかった」経験と持続する目的から、別の働きかけを選ぶ理由が読める。毎回異なる行動を強制しない。相手が止まれば声かけの継続や待機でもよい。謝罪・協力・新しい情報があれば、攻撃以外の意思も成立する。

## 7. 責務と非同期合流

- 共有状態・差分契約: 目的等の現在値と、明示的な更新・解除の意味を型で定義する。
- 経験投影: 本人の経験を集め、セリフと状況・結果を結び、短い窓と残る事項へ渡す。正準世界を推測しない。
- プロンプト構築: 型付き投影を自然文として配置し、共通説明を一度だけ渡す。
- LLM応答検証: 既存の合法候補・参照・意欲・発声・influencesと差分契約を検証する。
- job受理・適用: 入力を凍結し、job ID・generation・fence・sourceTickを既存機構で照合する。許可された差分を一度だけ適用し、行動は現在世界で判定する。

思考の遅延そのものは保持する。入力時点の状況認識は、その時点の本人の認識として扱い、現在の正準事実へ昇格させない。古い応答が新しい意識状態や履歴を巻き戻す設計は採用しない。フィールドのsource時点・適用条件と重要事項の競合は詳細設計で既存fenceに接続する。

## 8. 代案と今回の推奨

| 案 | 効果が期待できる点 | 弱点 |
|---|---|---|
| A: 現在のgoal/thoughtへ短い動機接続指示を足すだけ | 最小変更で効果を測れる | 欲求・意思と履歴を明確に継続できず、毎回の作文に依存しやすい |
| B: 状態ラベル＋短い経験履歴＋同一呼び出しの行動選択 | 目的を継続し、働きかけの理由と相手との応答を結びつけられる | 型・保存契約の改訂が必要。ラベルだけ増えて内容が空疎になる危険 |
| C: 行動の種類を強制的に変える | 見た目の反復を減らせる | 人物の意思や必要な継続を壊す。今回の課題への主案にはしない |
| D: 裁定の停滞を先に点検する | 選択した行為が成立しない停滞なら直接効く | 動機・会話の欠落は補えない。本案とは独立した原因候補 |

推奨はBを基本設計とし、実装を広げる前にAとBの同じ場面での比較ができる検証資料を作ること。Dを無視せず、入力と意思に変化があっても実行が進まない場合は裁定側の調査へ切り替える。比較用資料は次の実装・検証を支えるものであり、機能の代替納品にしない。

## 9. 効果の確認

同じ人物・目的・知覚・相手の発言を使い、少なくとも「要求を無視された」「目的に近づいた」「相手が協力した」「危険で衝動と目的が衝突した」「待機に理由がある」の場面を用意する。

見るものは、目的と行動のつながり、相手の直近の言葉・行動への応答、未解決事項の継続、変化に応じた意思の修正、正当な継続、知らない情報の混入、入力・出力の実トークンと呼び出し数である。異なる行動の数だけを品質指標にしない。

LLM-freeテストは型・知覚境界・差分・履歴・遅延合流を確認する。意味上の改善は同一場面の実モデル比較や試合の読解で確認し、ローカルテスト合格を代用しない。実モデル比較の予算・件数・合格閾値は後続の検証契約で提示する。

レビューは一名の独立agentが読み取り専用で行い、推奨、最も大きい懸念、よりよい代案、次の検証をまとめる。独立レビューは製品上の効果の実証や所有者受入ではない。

## 13. 独立レビュー反映と次の手

[レビュー記録](evidence/conscious-motivation-effectiveness-review-2026-10-06.md)はBの方向を推奨した。主な指摘は、ラベル追加の前に人物の動機材料が届いていること、経験した結果が意思へ戻ること、裁定停滞と動機不足を混同しないことである。細部の全面再設計や別方向への変更は勧めていない。

次の順序にする:

1. 凍結キャラ資料 → 顕在用投影 → 実送信入力の一経路を照合し、既存の価値観・coreNeeds・本人が自覚している目的材料がどこに届くか確認する。潜在用のcoreNeedsをそのまま顕在へ公開せず、自己認識・顕在度の境界を守る。根拠がない動機を足して穴を埋めない。
2. 停滞した一場面を意欲提案 → 競合/受理 → 裁定 → 本人の知覚結果へたどる。どの段階で進展が止まるかを確認し、実行側が主ならそちらの改善を先に選ぶ。
3. [比較用場面](conscious-motivation-effectiveness-cases-2026-10-06.md)の「要求無視／協力」の対を中心に、短い指示案と動機・履歴・状態案を比較できる詳細設計へ進む。入力が違う比較からラベル単独の効果を断定しない。

レビュー後の限定確認: `awareness-context.ts` は潜在characteristicsへcoreNeedsを明示的に渡すが、顕在はconsciousSelfのtendencies/background/actionPrinciplesを渡している。コンパイル時に動機をどこまで織り込むかは未確認。保存済み公開試合の両者の顕在入力では、characteristicsは各3件で、観測・圧力・問い返し・挑発等の行動傾向が中心。人物profileも技能と口調・役割の説明が中心である。これは入力の動機材料を点検する価値を示すが、全キャラの欠落や単調化の根本原因を証明しない。

追加の限定コード確認: `structured-character.ts` の `projectCharacterConsciousSelfV2` はbackground/tendencies/actionPrinciples/speechを投影し、coreNeedsを直接含めていない。`character-definition-v3.ts` の `compileCharacterBattleCompilerInputsV4` はその投影を使い、actionPrinciplesを空配列にし、consciousGuidanceを別のmemberとして保持する。`awareness-context.ts` の顕在入力構築にはconsciousGuidanceの明示転送がない。この経路だけでは既存の欲求や行動指針をそのまま読めず、他の記述へ同じ意味が含まれる可能性は残る。次の手は既存の自覚可能な動機・指針をどこへ渡すかの設計であり、キャラに新しい目的を創作することではない。

同試合のsequence4/turn2には、自由行動の現実判定が未確定という実況がある。終盤のjobだけではこの場面の提案・競合・裁定の履歴を再現できないため、段階2の追跡は未完了。人物が動機を持たなかったと決めつけない。
