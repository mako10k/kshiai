# 対戦実況 Fragment と再試行表示 — 要件候補 revision 1

- 状態: Proposed（この文書の正確な版に対するオーナーレビュー前）
- 日付: 2026-09-29
- 決定者: プロダクトオーナー
- 対象: 対戦から派生する実況の記録、生成試行、Streaming 表示、再試行
- 根拠: 2026-09-29 のオーナー指示。実況本文は Fragment 単位で Immutable、Narration は Fragment を追記し、正常に最後まで受信した Fragment だけを Commit する。失敗時は途中表示を保ち、再試行中の案内を出し、新しい Streaming が始まると未確定表示を入れ替える。実況の成否は Battle の正史に影響しない。後続の「OKです。では、設計や方針に固定化してください」は、この動作の記録を依頼している。

## 目的と権限境界

利用者は確定済みの実況 Fragment を順に読める。生成中は未確定の文字を Streaming で見られ、失敗と再試行を区別できる。対戦のターン、Beat、結果および確定イベントは Battle が所有し、実況の生成・配信状態はそれらを書き換えない。

この文書はオーナーの会話上の決定を要件候補として正確に記録する。既存の Accepted [ADR-0006](adr/0006-terminal-snapshot-narration-delivery.md) は途中の本文を公開しない方式を選んでおり、今回の未確定 Streaming 表示と矛盾する。要件候補の作成だけで ADR-0006 の状態は変わらない。後継 ADR はこの変更と維持する条件を明示する。

## 必須条件

**NF-1 対戦と実況の関係。** 一つの Battle に対して一つの論理的な Narration がある。Narration は順序付きの確定 Fragment を 0 個以上保持する。実況の行や worker の作成失敗は Battle の作成、進行、勝敗、確定イベントを取り消さない。物理的な Narration 行を Battle と同時に作ることは要求しない。

**NF-2 Fragment の確定。** 完成して Commit された Fragment の本文、順序、参照元は Immutable である。Narration は確定 Fragment を追記する。画面で連結した全文は表示結果であり、毎回書き換える累積本文を正本にしない。

**NF-3 生成試行と Commit。** 一つの Fragment の位置には複数の生成試行があり得る。Streaming 中に届いた文字は未確定である。生成元から正常終了を確認し、完成した本文を保存できた試行だけが Fragment を Commit する。途中失敗した試行の文字は確定 Fragment にならない。同じ位置への確定 Fragment の二重追記は防ぐ。

**NF-4 再試行の独立性。** 失敗後の再試行は別の試行であり、前回と同じ Streaming のチャンク列、タイミング、本文を再現する義務はない。二重 Commit の防止は、Streaming の完全再現とは別の整合性条件である。

**NF-5 失敗から再試行までの表示。** 生成試行が途中で失敗した場合、画面はその位置の未確定な途中表示を残す。再試行が予定されたら、「ナレーションをやり直しています」に相当する案内を添える。新しい試行の最初の本文チャンクを受信した時点で、同じ位置の古い未確定表示と案内を消し、新しい Streaming 表示に切り替える。他の位置の確定 Fragment は維持する。

**NF-6 再試行が終わった後の失敗表示。** 再試行が終了しても Fragment を Commit できず、次の再試行が予定されない場合、途中表示は残し、再試行中の案内を終了して失敗を明示する。再試行回数、間隔、自動・手動の選択はこの要件では定めない。

**NF-7 確定結果と通信。** Fragment の Commit 後、画面は確定本文を表示する。画面との通信断は生成失敗と同一視しない。再接続で確定済み Fragment を読み戻し、受信し損ねた Streaming チャンクがあっても確定本文へ表示を合わせられる。同じ途中 Streaming の再現は要求しない。

**NF-8 対戦正史からの独立。** 生成、Streaming、再試行、Commit、配信、失敗の各結果は Battle のターン、Beat、確定イベント、勝敗を変更しない。Narration はそれらの確定情報を入力として参照する。

## 受入時に確認する振る舞い

1. 正常な試行は、未確定表示から一つの確定 Fragment になり、以後の再読込でも同じ本文と順序を返す。
2. 途中失敗した試行は Fragment を増やさず、途中表示と再試行案内を維持する。新しい試行の最初の本文チャンクでその位置だけ表示を入れ替える。
3. 再試行の文面が前回と違っても正常に表示し、正常終了後の Fragment だけを確定する。
4. 再試行が予定されなくなった場合は途中表示を保持して失敗を表示し、確定 Fragment は増えない。
5. 画面が途中チャンクを取りこぼしても、確定 Fragment の読戻しで全文を表示できる。通信断だけで生成試行を失敗扱いしない。
6. 以上の成功・失敗のいずれでも Battle の確定状態と結果は変わらない。

## 既存権限と未決事項

- [ADR-0006](adr/0006-terminal-snapshot-narration-delivery.md) の「公開 prose は terminal snapshot のみ」という決定には後継 ADR が必要である。一方、対戦の確定が実況を待たないこと、入力の固定、順序、durable outbox、worker fencing、確定イベントの再接続可能性は維持対象として後継 ADR に渡す。
- [ADR-0016](adr/0016-scene-beats-batched-narration.md) と [ADR-0017](adr/0017-public-turn-intra-turn-beats.md) の Turn / Beat の意味は、この要件で変更しない。Beat と Fragment の正確な対応数、Beat 以外を語る Fragment の参照方法は設計判断として残す。
- 正式な適用開始時点、既存・進行中対戦と既存クライアントの扱い、リロード後の未確定途中表示の復元、複数の生成・配信接続の競合処理は未決である。この文書は移行、配備、production データ変更を承認しない。
- Exact なイベント名、ID、Transport、保存形式、再試行上限は後続の設計・実装で定める。要件より強い Streaming 再現保証をそれらから導かない。

## 自己レビューと次の審査入力

オーナー指示を NF-1 から NF-8 に分け、既存 ADR-0006 との衝突と未決の適用範囲を明示した。現行実装や試験結果はこの要件の権限根拠にしていない。独立レビューでは、Immutable な確定本文と失敗した未確定表示の境界、二重 Commit 防止と Streaming 再現不要の両立、Battle 正史への非干渉、既存 ADR の処置を検査する。正確な snapshot とレビュー経路は [review input](narration-fragment-requirements-v1-review-input.md) に記録する。
