# 裁定入力の表記圧縮 第1版

## 要件

所有者指示: 正確さを優先し、余分なトークンを圧縮する。まず重複除去と配置整理に絞り、能力資料の意味的な絞り込みは行わない。顕在側は単調化防止と合わせて別途検討する。

## 基本・詳細設計

現行のawareness裁定dispatchは、既に投影されたJSON資料を `prompt-prose.ts` で全項目文章化している。その反復的な構造説明と二言語の型説明を、専用rendererの短い箇条書きへ置き換える。

専用module `adjudication-prompt-prose.ts` は表記だけを担当する。原キー、値、型、null、空文字、空配列、空object、配列順序、全階層を保持する。文字列は引用・escapeし、資料内の改行や指示文が構造と混ざらないようにする。object内のundefined省略は従来と同じ。循環、非JSON値、32を超える深さ、20,000を超える項目は明示的に拒否する。

統合先は `openai-compatible.ts` のawareness dispatch guard内だけ。system指示、出力schema、SDKの利用トークン記録、厳密な応答検証、モデル・時間・回数・保存状態・旧経路は変更しない。実際に短縮した送信文が既存のadmissionへ渡る。追加LLM要約や資料の意味的な選別は行わない。

正準状態の所有権や裁定・公開契約は変わらないため、この表記修正で新しいアーキテクチャ方針を導入しない。既存ADRの境界を保持する。

## 検証

型・否定・数値・ID・順序・空値の保持、入力制限の拒否、代表資料の文字数削減、dispatchとadmissionの送信一致を既存テストと回帰テストで確認する。実トークンの削減率は新たなSDK実測まで未確認。公開反映や有料試験はこの作業に含めない。

実装後の検証: `npm run typecheck` 成功、`npm test` の選択された29件成功、専用renderer・既存dispatch・厳密な裁定結果の直接実行14件成功。新規テストは直接実行で確認しており、SealGraphによる全体テストの採用にはまだ登録していない。

20個の正準rootを含む合成資料では6,334文字から6,181文字へ短縮（2.4%）。実試合資料でも実トークン数でもない。今回の変更は控えめな構造表記の削減であり、大幅削減を達成したとは扱わない。残る詳細・ルール本文を削る作業は行っていない。
