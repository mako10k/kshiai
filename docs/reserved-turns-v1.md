# 予約ターンパイプライン v1

Accepted ADR-0072 revision1。新方式の時計はturnのみ。通常ターンはA/B各1回を並列、裁定1回、公開結果から実況を最大1回。最大5予約は行動を増やすためのノルマではない。

キャラクター出力は`actions: {id,intent,targets,condition?}[]`、任意speech、必須memory。行動は試みであり、予約時点で成功や損害を確定しない。inputは本人資料・知覚・前ターン結果・順位記憶・参照可能な対象。相手の記憶と予約を渡さない。通常攻撃/技も自由な試みと同じ裁定へ渡し、旧候補リストで意図を黙って消さない。

サーバーは予約index、ターン開始initiative降順、同値時turn偶奇の先行側で順序を決める。裁定にはその順序と凍結世界・不変資料を渡す。裁定出力は予約IDごとの結果・理由・正準更新・観測可能な結果。各結果は直前までの裁定後stateRevisionを参照する。サーバーは作業コピーへ順次適用し、全列が有効なときだけ永続世界と双方の記憶を一括commitする。世界内部のrevisionは整合性番号でありゲーム時計ではない。

正準更新DSL v1は既存の型付きworld operationとhp/mp/staminaの増減。型・存在・残量・上限・revision・予約の完全性を機械検証し、成否の意味を別の機械分類で再裁定しない。成功/部分成功には具体的効果が必要。失敗には必要に応じて消耗等を記録する。中止は変更なし。戦闘不能の本人は後続を中止する。裁定列はLLMの一回の推論であり、中間のサーバー状態を逐次再入力する方式ではない。

保存は新しい不変束縛とprivate runtime。送信前に固定request IDと入力digestを予約し、成功応答はpreparedとして保存。片側失敗・未知送信・不正裁定でworld/memory/turnを先に変えない。成功済みpreparedのみ再利用、未知送信を再送しない。診断と利用台帳は失敗時も残す。

既存対戦とapplication v0.24.0-rc.9は旧方式を継続。実装・無料のローカル検証と、実モデル品質・料金・本番配備の証拠は区別する。

初期運用上限は最大36ターン、試合全体10分、各要求60秒、作成時の遭遇生成を含め物理試行200回。制限到達は勝敗を捏造せずincompleteとして停止する。既知のHTTP429のみ最大2回、Retry-Afterまたは指数待機を使って再試行し、上限・期限に含める。通常の4論理呼出しと物理再試行回数は区別する。

配備時は追加マイグレーション0038_reserved_turns.sqlを先に適用する。application v0.24.0-rc.9は試合束縛形式 v7を実行できないため、切り戻し時は新規作成を閉じ、既存の試合束縛形式 v7を処理できる実行系を保持する必要がある。旧試合の形式変換や削除は行わない。不正なJSON応答もprivate runtimeに保持し、公開停止理由は技術コードだけに限定する。

実況はターン内で生成し、正準更新と同じトランザクションで既存の公開実況エントリと配信イベントへ完了済みとして書く。非同期workerのclaim・outboxは作らず、追加LLM呼び出しも行わない。公開完了検証は試合束縛形式 v7の各ターン4要求・物理台帳との対応・公開実況完了を確認し、旧tick/非同期実況の証拠を要求しない。
