# 予約ターンパイプライン v1

Accepted ADR-0072 revision1とADR-0080 revision2。新規対戦は予約ターンポリシー v8・計画/裁定プロンプト v7・出力形式 v4。新方式の時計はturnのみ。通常ターンはA/B各1回を並列、裁定1回、公開結果から実況を最大1回。最大5予約は行動を増やすためのノルマではない。

キャラクター出力は`actions: {id,intent,targets,condition?,mechanics}[]`（mechanicsは行動種別と、技の場合skillId）、任意speech、必須memory。行動は試みであり、予約時点で成功や損害を確定しない。inputは本人資料・知覚・前ターン結果・順位記憶・参照可能な対象。相手の記憶と予約を渡さない。通常攻撃/技も自由な試みと同じ裁定へ渡し、旧候補リストで意図を黙って消さない。

サーバーは予約index、ターン開始initiative降順、同値時turn偶奇の先行側で順序を決める。裁定にはその順序と凍結世界・不変資料を渡す。裁定出力は予約IDごとの結果・理由・正準更新・観測可能な結果。各結果は直前までの裁定後stateRevisionを参照する。サーバーは作業コピーへ順次適用し、全列が有効なときだけ永続世界と双方の記憶を一括commitする。世界内部のrevisionは整合性番号でありゲーム時計ではない。

正準更新DSL v1は既存の型付きworld operationとhp/mp/staminaの増減。型・存在・残量・上限・revision・予約の完全性を機械検証し、成否の意味を別の機械分類で再裁定しない。成功/部分成功には具体的効果が必要。失敗には必要に応じて消耗等を記録する。中止は変更なし。戦闘不能の本人は後続を中止する。裁定列はLLMの一回の推論であり、中間のサーバー状態を逐次再入力する方式ではない。

保存は新しい不変束縛とprivate runtime。送信前に固定request IDと入力digestを予約し、成功応答はpreparedとして保存。片側失敗・未知送信・不正裁定でworld/memory/turnを先に変えない。成功済みpreparedのみ再利用、未知送信を再送しない。診断と利用台帳は失敗時も残す。

既存対戦とapplication v0.24.0-rc.9は旧方式を継続。実装・無料のローカル検証と、実モデル品質・料金・本番配備の証拠は区別する。

新規対戦の公開上限は12ターン。各ターン終了時に戦闘不能を判定し、12ターン終了時は既存の残存能力スコアで勝敗を確定する。同点だけ引き分け、戦闘不能は規定ターン判定より優先する。旧36tickを36公開turnへ読み替えた実装は移行誤りとして修復し、保存済み旧ポリシーは変更しない。試合全体のハード上限30分・ソフト10分、通常要求ハード120秒・ソフト60秒、裁定ハード300秒・ソフト180秒、物理試行200回を束縛する。予算/期限の技術停止と、正常な規定ターン勝敗を区別する。既知429のみ最大2回再試行し、未知送信は再送しない。正常呼び出しはキャラクター2・裁定1・実況1、完走の通常最大は遭遇1を含め49試行。

配備時は追加マイグレーション0038_reserved_turns.sqlを先に適用する。application v0.24.0-rc.9は試合束縛形式 v7を実行できないため、切り戻し時は新規作成を閉じ、既存の試合束縛形式 v7を処理できる実行系を保持する必要がある。旧試合の形式変換や削除は行わない。不正なJSON応答もprivate runtimeに保持し、公開停止理由は技術コードだけに限定する。

正準世界・双方の記憶・裁定列・位相receiptと不変実況入力/outboxを同じトランザクションで先に確定する。実況は既存の永続キューとfenced workerで順次生成する。正準状態は実況の完了を待たず、実況は正準状態・勝敗・記憶・ratingを変更しない。次の実況は先行実況のterminal snapshotを待ち、結果表示は当該対戦の実況が終端になるまで勝敗・ratingを隠す。失敗時も安全な公開結果と確定発話/判定だけからterminal fallbackを表示し、未知送信を再送しない。公開完了検証は各ターン3正準要求+1実況要求と物理台帳・公開完了を照合する。

通常攻撃STA3、技の不変費用、同じbasic_attack/skill/reflectの反復STA2/4はサーバーが適用する。自由行動の追加STA・一回限りの防御露出・部分実行は根拠と対象snapshotを持つ裁定提案から機械検証する。自由行動文の反復や失敗枠への一律資源罰は設けない。疲労の現在感覚・結果feedback、本人の性格資料、知覚可能な確定発話を次ターンへ渡す。

予約ターン裁定プロンプト v2は、各order項目へ実行直前のbaseRevisionを明示する。最初はstate.revisionそのもので、サーバーは従来どおり厳格照合する。LLM出力の番号を補正しない。保存済み予約ターン裁定プロンプト v1は従来の入力と指示を維持する。application v0.25.0-rc.1の失敗記録を残し、新規対戦のみapplication v0.25.0-rc.2でプロンプト v2を選択する。
