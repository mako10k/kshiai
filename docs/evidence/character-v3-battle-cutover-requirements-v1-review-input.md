## このレビューで決める境界

**INSIDE（要件候補が決めること）:** 新規対戦が両者 V3 に限られること、切替前から未完了の対戦の破棄の意味と対象、完了済み履歴を保持すること、新規 V3 対戦の不変リビジョン結合、旧要件・ADR のどの部分を保存しどの部分を変更するか。受入閾値は、これらがオーナーの指示と互いに矛盾せず、旧対戦の継続を到達条件に残さないことである。

**OUTSIDE（後続 ADR／設計／適用に渡すこと）:** 削除 SQL やスクリプトの形、依存レコードの具体的処理、切替 release と時刻、実データ件数、障害回復手順、API の関数名、Stage／production の実行。例えば、対象未完了対戦を消すという要件はここで判断するが、どのトランザクションで何件ずつ消すかは適用設計で決める。

**BOUNDARY_DISPUTE:** `finished` と判定できない破損済み履歴の扱いは、実データを見ないと未完了か完了済みか確定できない可能性がある。この候補では未完了と確定できた対象だけを破棄し、不明な行の自動削除を認めない。独立レビューでは、この分類がオーナーの「途中」の範囲を満たすかを確認する。

## 初回レビューの論点

1. 「破棄」を、切替前から未完了の battle を保存データから削除し、閲覧・再開・再送から消すこと、とした範囲は指示に一致するか。完了済み履歴は対象外という境界は適切か。
2. Accepted ADR-0010 とキャラクター互換要件 revision 6 の歴史的 battle 可読性を、未完了対戦について後発の破棄指示に従って変更し、完了済み履歴と旧 generation bytes を維持する整理に矛盾はないか。
3. 新規対戦の V3-only と V3 authoring policy の別 identity、両者の不変 generation の結合、直接 API を含む拒否条件が、既に決定済みの製品動作を十分に表しているか。
4. 破棄済み旧 battle の idempotency response や関連レコードが残っても再開・復活できないという要件は明確か。具体的な削除手段は後続の設計へ渡す。

## 受入後に改める下流範囲

- [V3 Stage 子計画](../character-v3-stage-trial.pert)の `vt102`: 新規 V3 対戦の不変結合・全 consumer は残す。「未完了の旧対戦を継続する」ための実装・試験は外し、切替時破棄と完了済み履歴の readback を別々に確認する。
- [親計画](../character-semantic-migration.pert)の `cc305`、`cc314`、`CS_STAGE_TRIAL R2`、`CS_FINAL`: 「historical battles remain readable」を、完了済み履歴は保持し切替前の未完了対戦は破棄する、という対象別の条件に直す。既存の実績や以前の判断記録は書き換えない。
- [cc318 監査](cc318-v3-battle-cutover-audit-2026-09-28.md): 監査時点の事実は残し、manifest なし未完了対戦の継続・復元を次の実装必須項目として扱った勧告だけを後続のオーナー決定で失効したと追記する。
- Accepted ADR-0010／ADR-0030 とキャラクター互換要件 revision 6 の権限関係は、必要な要件受入と後継 ADR で明示する。現在の候補とレビュー入力だけでは、実装や対戦データの削除は開始しない。
