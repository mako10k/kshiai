# V3試用ソースの静的検査基準変更候補 v1

状態: Proposed。未承認・未適用。対象タスク: vt104。

## 目的と権限
Googleログイン前の試用準備を進める際、現在のV3ソースがLizard検査の既存総量上限を超える問題に対する、所有者判断用の候補である。実装済みという事実や226テスト成功は、この変更の権限にならない。
現行の config/lizard-baseline.json と、静的検査を要求するAccepted ADR・設計を現在の基準として維持する。採用する場合のみ以下の5値を変更する。その他の要件、ADR、機能仕様、外部バージョン、名前空間には変更を提案しない。

## 提案する規範的変更

| 指標 | 現行 | 提案 |
| --- | ---: | ---: |
| CC 上限超過関数数 | 121 | 134 |
| CC 最大値 | 92 | 96 |
| CC 超過総量 | 1369 | 1623 |
| 関数長 上限超過関数数 | 67 | 72 |
| 関数長 超過総量 | 7390 | 7571 |

CC閾値15、関数長閾値100、引数閾値6、関数長最大許容733、引数指標の許容値5/11/10、走査対象と除外、Lizardバージョン1.23.0を維持する。検査をスキップしない。変更後の増加を引き続き検出する。

## 根拠と限界
Node22による現在の試用ソース検証では、226テスト、型検査、重複検査が成功し、Lizardが不合格だった。観測値はCC134/96/1623、関数長72/639/7571、引数5/11/10。依存修正はundici7.29.0→7.29.1の2マニフェストだけであり、実行時TypeScriptは変更していない。
これらは非規範的な比較証拠である。テスト成功は複雑な関数の保守性や実環境の動作を保証しない。一部fixtureの長さ計測にはパーサーの区間認識の影響が疑われ、未確認である。

## 代替案・リスク
A: 上記を新基準として受け入れる。現状の複雑度を許容するため、旧基準より検出制約が緩くなる。読みづらさや将来の修正リスクを解消しない。承認後も全CIと実環境証拠が必要。
B: 現行基準を維持し、責任分割・関数整理で超過を解消する。基準を緩めずに済むが、戦闘公開DTO、切替HTTP受付、ナレーションのlease/transaction等の動作を保持する検証が必要。内部作業追加3〜7時間の暫定見積り、確度低。計測区間の検証後に更新する。
推奨: まず独立レビューでAの妥当性と計測の妥当性を確認し、その結果を所有者判断に戻す。Aの採用を推奨・確定するものではない。

## 受入条件と対象外
採用された正確な要件版に従い、5値以外の設定が維持されること、同一ソースで静的検査・型検査・テストが成功すること、Hosted CIの必要4検査が成功することを確認する。基準変更だけで試用完了とはしない。
本候補の受入は、実装適用、コミット、push、PR/タグ作成、デプロイ、DB破棄、共有停止、認証設定変更、Googleログイン、課金呼出しを新たに許可しない。それぞれの既存権限と未決定事項を別に照合する。

## 自己レビュー
現行基準を無断で上書きせず、先行権限を保持した提案である。対象は5集計値のみ。外部互換性や利用者データの変更はない。現状値の許容が本来の品質要件と整合するか、計測区間が妥当かは未決定。性能・保守性の改善は未達。所有者の一次レビュー後、凍結した本候補を独立レビューする。
