# 意味移行 V4：不正な断片で有効値を上書きしない修正

## 概要

実LLMの prompt-v3 観測で確認した「不正な修正操作をいったん候補へ反映し、最後の全体検証で初めて失敗する」問題を、prompt-v4 として是正した。各操作の対象断片を反映前に検証し、不正な操作だけを拒否して直前の有効値を保持する。有効な兄弟操作は独立して反映し、拒否理由は次の限定修正入力へ渡す。

## 主要な差分

- `character-semantic-migration-prompt-v4` を追加した。消費済みの v1〜v3 の再生結果は変更しない。
- copy / move / transform / synthesize の対象値を一時候補へ書き、対象パスに属する V3 スキーマ違反を操作反映前に検出する。
- 違反時は `operation_fragment_schema_invalid` を記録し、その操作を適用済み一覧へ加えない。以前の有効な断片はそのまま残す。
- V4 の修正プロンプトには、拒否されたパスと意味的依存先だけを直し、直前の有効値と有効な兄弟操作は保持する規則を追加した。

## 検証結果

- 回帰テストでは、同じ `orderedActionRefs = null` を V3 と V4 の両方へ入力した。
  - V3 は履歴互換のため従来どおり null を反映し、後段の全体検証で候補を失う。
  - V4 は不正操作を拒否し、既存の `basic-action` fallback を保持する。
  - 同じ応答内の有効な優先度変更は V4 でも反映される。
  - エラーは次の修正入力へ入り、完全候補にも保持された fallback が含まれる。
- 全780テスト、全workspaceの型検査、本番build、jscpd、Lizardのリポジトリ閾値に合格した。
- ADR-0030 の個別チェックは成功した。全ADRチェックには既存の ADR-0015 / 0016 / 0017 / 0019 の問題が残る。

## 論点・対案

- 採用：V4だけに反映前検証を導入する。履歴再現性と新規試行の安全性を両立できる。
- 不採用：V3の統合処理を直接変更する。コード量は少ないが、消費済みreceiptの再生結果を変え得る。
- 不採用：最後の全体検証だけに任せる。不正候補のactivationは防げるが、有効だった断片まで失って修正が収束しない問題を残す。

## この修正で解決していないこと

スキーマ上は正しいが事実に反するレビュー指摘（例：妥当な優先度を変更する誤指摘）は防いでいない。公開発言と非公開の自己認識を混ぜた由来情報の開示継承も別論点である。実LLMでのV4収束、B6、現在世代のactivation、本番変更も未実施。

Sealgraph 自体については、長時間の `impact` / `stale` と進捗表示不足を [mako10k/sealgraph Issue #13](https://github.com/mako10k/sealgraph/issues/13) として発行し、本文を読戻し確認した。Sealgraph の既存ローカルWIPは変更していない。
