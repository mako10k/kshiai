# ADR-0032 revision 1 オーナーレビュー用・全文日本語訳

この文書は、英語の正本 `docs/adr/0032-bind-v3-characters-to-versioned-battles.think`
のレビュー支援訳であり、第二の正本ではない。Markdown版は同じ判断の表示用投影である。
対象はADR-0032 revision 1全体。状態は **Proposed** で、受入はまだ記録されていない。

## 問題と根拠

- **P1 問題:** 最初のV3対V3 Stage試行では、新しく始める対戦にV3キャラ2体の世代を固定し、V4コンパイラ入力を再読込後も全ての対戦利用箇所へ渡す必要がある。現在の`startBattle`とmanifestの版は、その組を表現しない。
- **E1 上位判断:** 受理済みADR-0010は、互換性のある現在の正確な世代を、作成処理で書込みをせず読み取って結合することを求める。受理済みADR-0030は、`CharacterBattleCompilerInputsV4`と`character_generation_v3`という由来を定義する。受理済みADR-0028は、対話V3のcompact投影、activation、心理反応、完全な識別子の組を固定し、混在した組を拒否する。
- **E2 現状:** リビジョン`067cb01`時点の`startBattle`はV2 envelopeを読み、`character_generation_v2`と`compilerInputsV2`を保存する。manifestの第3版への変更は対話設定の組を変更するだけで、キャラの出所はV2のままである。
- **E3 オーナーの範囲:** 最初のStage試行には新規V3キャラ2体を使い、V3対V2は含めない。PERTでは`vt101`が登録・選択、`vt102`が対戦への結合・利用、`vt103`が両者を統合する。

## 比較した案と未決定事項

- **既存manifest第3版の意味をV3キャラ用に変える:** 差分は小さいが、既存の第3版対戦の履歴的意味を変えてしまう。
- **V2/V3混在を扱える汎用manifestを今作る:** 対応範囲は広いが、初回試行に不要な実行・互換動作を増やす。
- **V3キャラ2体専用の別manifest版を作る:** 新しい保存・利用分岐の負担はあるが、既存の意味を維持し、今回の範囲に合う。提案する案はこれ。
- **U1 / OWNER_ACCEPTANCE:** この正確な保存形式と利用契約は、まだオーナーが受け入れていない。`Proposed`のままでは実装権限にならない。このrevision 1の正本とレビュー範囲を提示し、明示的な`ACCEPT`または`REVISE`を得る。Stage書込みは別の権限を要する。
- **U2 実装時の境界:** 現在のV3世代readerは互換性を報告するが、非互換の現在世代を自ら拒否はしない。統合した対戦作成を主張する前に、`vt101`が現在ポインタとreadiness、対戦で実際に必要なcapability集合を実装・検証する。

## 提案する判断

- **D1:** V3キャラ世代2体で作る対戦には、独立した`BattleAssetManifestV4`を用いる。両側とも既存の`BattleCharacterAssetBindingV4`契約を用い、正確なアセット・世代ID、内容digest、不変の戦闘用snapshot、`character_generation_v3`基本行動由来、`CharacterBattleCompilerInputsV4`を保持する。ADR-0028の対話schema 3のcompact投影、activation識別、`psyche-reaction-policy-v1`、正確なキャラdigest、識別子の組全体による判定を維持する。キャラcompilerの欄はV3からV4に進め、他の固定されたアセット・ルール識別情報は維持する。
- **D2:** 対戦作成は、`vt101`の現在ポインタ・互換性・準備完了判定を通して、各キャラの現在のV3世代を読む。欠落、ID不一致、必要capabilityの非互換、V2/V3混在なら失敗する。対戦で必要なcapability集合はV4を利用する箇所と一致させ、統合した作成の前に`vt101`とともに検証する。世代追加、現在ポインタ移動、生成呼出し、暗黙のV2変換はしない。結合部の準備は独立に進められるが、ローカルで実際に作成できることの最終証明は`vt101`を待つ。
- **D3:** 実行、再試行、再読込、ナレーション、表示、観測は固定されたV4の組を使う。V3行動規範を行動選択に使い、顕在意識向けのガイダンスを機械的な選択条件に転用しない。登録された代替行動は、ADR-0030のとおり合法性の再確認後に適用し、矛盾のreceiptを残す。V4入力をV2/V3の規範へ無理に変換せず、可変の現在キャラを権威ある入力として読み直さない。
- **D4:** 第4版を読み書きできるようにする一方、既存第1～3版の意味を変えない。既存対戦の自動移行・再結合はしない。この判断は初回の全員V3試行だけを対象とし、混在対戦、V2移行、provider生成、Stageでの有効化、本番昇格は決めない。

## 結果・検証境界

利点は、全員V3の対戦で正確な不変世代を追跡し、再試行・再読込後も同じ振る舞いを保持できること。負担はmanifestの新しい版とV3専用の利用経路であり、利用箇所を漏らすと第4版の拒否や可変データの誤読が起こり得る。既存V2対戦と対話manifest第3版は変更しない。`vt101`およびrelease・Stage工程は別である。

検証するのは正確な世代・digestの結合、混在や不正な組の拒否、保存・再読込、キャラ編集後の再試行、V3規範・ガイダンス・代替行動の利用、ナレーションと公開表示、既存第1～3版の回帰である。fixtureのschema検査だけでは完了としない。このADRだけではStage操作や実戦を許可しない。
