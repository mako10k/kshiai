# ADR-0030 B5 — 意味変更・全体レビュー・限定修正のローカル検証

2026-09-10。承認済みADR-0030 revision 1 / 専用PERT cb205。
基点は作業ブランチの e0f2224。今回の変更はローカル未コミット。

## 結果と機能差分

B4までの「凍結した入力・要求・応答を保存する契約」に、B5の処理を接続した。
次の操作を受け取り、完全な候補を検証して所有者レビューへ返す。現在世代には反映しない。

| 操作 | 意味 |
|---|---|
| copy | 同じ役割・同じパスの元値をそのまま継承 |
| move | 元値を別欄へ移し、旧欄が残る場合は空にする。必須欄なら全体検証で修正を要求 |
| transform | 出典を示して役割・値を変換 |
| synthesize | 元情報からの導出か、モデルによる新規生成かを明記して補完 |
| retire_to_capsule | 対象の元値を退避し、現在候補の対象欄を空にする |
| defer | 不足理由・候補出典・必要とする能力を明記し、利用時まで保留 |

正常部分はサーバーが継承する。応答の一部が不正でも、有効な操作を保持する。
修正はエラー箇所だけに限定せず、構造上の依存先・生成側の申告・レビュー指摘を合わせて
許可範囲を作る。範囲全体の書き直しは要求しない。毎回の統合後に全体を構造検証し、
凍結元情報と候補全体を使う別要求で意味を再レビューする。
旧規範の短い方針と機械的fallbackの優先順位を、同じ修正で揃える回帰試験を含む。

上限は初回生成＋初回レビュー＋2回の修正と再レビュー、計6要求。
各要求の識別子・親・内容・会計・応答をB4へ記録し、保存済み応答から再構成する。
結果不明の要求は再送しない。明示的な失敗会計と、結果不明で会計を推測できない状態を分離する。

パス・ID・名前/根拠参照・元値の消失・戦闘能力・開示・consumerTags・必要な利用能力を検証する。
新規値の生成と、元の私的情報の公開先への転送を区別する。
既に定義された欄単位の開示上限内で、元の対象値が存在しない明示的な新規生成は許す。
由来の意味的な正しさは構造だけでは証明できず、全体レビューと所有者確認を必要とする。

退避内容は変更前の正確な値を持ち、256 KiBの最終上限を考慮して事前検査する。
候補・操作・ユーザー向け差分には型付きデータを渡し、内部受け渡しをString経由にしない。

## 作業中のRCAと対処

1. 再開要求の同一性不一致：
   新しいパス列挙がJSONオブジェクトの挿入順に依存していた。
   B4の正規化保存で順序が変わり、派生したパス配列と要求ダイジェストが変わった。
   パス順を固定し、保存前後の要求内容・ダイジェスト・4要求の修正後再開まで確認した。
   同一性検証は緩和していない。再開試験は検出手段であり、欠陥を作った原因とは区別する。
2. 新規生成の過剰拒否：
   出典なしを一律に開示権限の新設と扱い、既存の欄単位の上限内での新規生成まで拒否していた。
   元の対象値がない明示的な新規生成を区別した。私的出典の不正な転送とconsumerTagsの
   権限拡大検証は維持。新規生成の正例・不正転送の負例で確認した。
3. 開発中の型互換：
   ES2022の型環境にないfindLastを新規コードが使っていた。
   複製した配列を逆順でfindする形に改め、コンパイラ設定を広げずに確認した。

採用した因果判断と実装判断は、先行するCLI LLMTHINK監査でfatal/error/warning=0を確認。
判断記録は同ディレクトリのB5 action-plan / replay-ordering-rca /
synthesis-disclosure / local-compatibility / validation-refinement / local-verificationのthinkファイルに保存した。

## 根拠と実装判断

## 限界と次の接続点

実providerは呼んでいない。provider portはテストダブルで検証しており、
実モデルの意味判断・コスト・対応する構造化出力の品質は未測定。
availableCapabilitiesは明示的な呼出元の能力一覧であり、稼働環境のcompiler導入証明ではない。

次はB6：正確な候補の所有者受入、候補・退避・receiptをまとめたappend、
現在世代のCAS、再開・drift・rollbackを実装する。
B5は常にactivated=falseを返し、現在世代、設定、schema-3 authoring policyを変更しない。
一般の作成/戦闘/read経路には接続していない。実provider・展開・本番変更は後続の別承認。
V3の実際のconsumer統合と全受入条件の追跡はB7以降の総合確認を必要とする。

IPv6非対応、先行PostgreSQL試行のpublic全体への影響未確定、
既存ADR全件チェックの未解決は保持する。今回それらへの接続・書込み・推測による修復は行っていない。
