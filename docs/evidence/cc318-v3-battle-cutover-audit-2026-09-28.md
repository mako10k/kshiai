# cc318: V3-only 新規対戦と既存対戦のリビジョン固定監査

- 監査対象: `codex/cc304-focused-revise` の `cc2e2cef8c523d3cdd474fe3a4f897da2edb92f8`。2026-09-28 の読み取り専用のソース監査であり、Stage、実データ、動作中サービスを観測した結果ではない。
- オーナー決定: V2 キャラクターでの**新規戦闘は廃止**し、新規戦闘の両者は V3 とする。過去の対戦の続きは、対戦作成時に記録した両者のリビジョンを使う。V2→V3 移行は Neva 対 Rio の初回 V3-only Stage 試行より後であり、V2–V3 混在戦を新設しない。この決定の一部は[現行親計画](../character-semantic-migration.pert)の `cc318`、`CS_STAGE_TRIAL R2` と[子計画](../character-v3-stage-trial.pert)の `vt101`、`vt102` に記録されている。計画自体を上位の仕様権限とは扱わない。
- 判定語: **観測**はこの checkout のコード・Accepted 文書から直接読めること、**矛盾**はオーナー決定と対象コードが両立しないこと、**不明**は保存済みデータまたは実行の証拠が不足することを示す。

## 監査境界と仕様の対応

この監査で判定するのは、オーナー決定から現在の選択、作成、再送、継続、表示までの経路にある不一致と、最初に修正すべき下流の成果物である。新しい要件・ADR の受入、コード修正、既存 battle の補完、Stage 試行、配備は後続段階である。manifest がない保存済み battle に作成時の不変情報が残るかは境界上の未解決事項であり、実データを推測しない。

| オーナー条件 | 現在の上位文書と効力 | 下流の所有範囲 |
|---|---|---|
| 新規戦闘は両者 V3、V2 新規戦闘は廃止 | [ADR-0010 §Decision](../adr/0010-structured-selectable-asset-envelope.md#decision) は互換な ready 世代のみの選択・作成と不変結合を規定するが、V3-only の世代境界を明記しない。[Accepted 要件 revision 6 §§Authority disposition, Compatibility](../character-v2-compatibility-requirements-v6.md#authority-disposition) は V2-only 選択権限の後継 ADR による変更と、旧世代・旧 battle の保持を要求する。受入対象は[受入記録](../character-v2-compatibility-requirements-v6-acceptance.md#オーナー判断と履歴)で固定されている。[Accepted ADR-0030 D3/D12](../adr/0030-llm-assisted-character-semantic-migration.think) は V3 の新しい compiler identity と schema 3 authoring policy を定めるが、authoring policy を新規対戦の V3-only switch と同一視できない。今回の全面廃止は後発の直接のオーナー決定であり、これらの古い文書から勝手に導出しない。 | `vt101`: V3 登録と選択。`vt102`: V3×V3 の結合、実行・表示 consumer、V2／混在新規作成の拒否。`cc305`: Stage 経路のレビュー。`cc314`: 実 Stage 試行の roll-up。 |
| 過去 battle は作成時の両者のリビジョンで継続 | [ADR-0010 §Decision/Compatibility/Verification](../adr/0010-structured-selectable-asset-envelope.md#decision) は exact generation と snapshot の読み取り専用結合、既存 manifest の維持、編集後の retry/resume/narration/replay 不変性を規定する。[Accepted revision 6 R19](../character-v2-compatibility-requirements-v6.md#append-only-execution-receipts-and-retry) は旧 battle が記録済み世代に結合したままとする。[Accepted V3 authoring requirement revision 5](../character-v3-authoring-requirements-v5-acceptance.md) は作成・修正・移行を受理し、ADR-0010 の binding を保存するが、新規対戦選択の詳細は定義しない。 | `vt102` の歴史的 continuation と回帰確認。`cc305` の Stage 経路レビューに未解決リスクを引き継ぐ。 |

|---|---|---|
| 自分のキャラ選択、相手候補、random/auto | **矛盾。** UI は `selectable: true` と `/api/match/candidates` を使い、random/auto も character ID を選ぶだけで世代版を指定しない（[MatchPage.tsx 92–123, 281–308](../../frontend/src/pages/MatchPage.tsx)）。自分の一覧 DTO の `selectable` は compatibility `ready` 判定のみ（[characters.ts 174–202](../../backend/src/repositories/characters.ts)）。相手候補の `listReadyCharacterIds` は `g.schema_version = 2` を要求する（[character-assets-v2.ts 1569–1594](../../backend/src/repositories/character-assets-v2.ts)）。どちらも V3-only の候補契約にはなっていない。 | `vt101` の選択 read model と UI/候補 API の接続条件。V3 を含み V2 を除く自分・相手・random/auto の試験。 |

## 境界、優先順位、次の判断

1. **監査境界内:** 現コードでは新規 V2-only が残り、新規 V3-only は成立していない。両者の不変 ID/digest/snapshot を記録する仕組み自体はある。manifest なし旧 battle の mutable-row fallback は、オーナーの継続条件と両立しない可能性が具体的にある。
2. **後続成果物:** 直接のオーナー決定は明確なので V2 新規戦闘の可否を再質問しない。現行 Accepted requirement/ADR が V3-only 新規対戦と authoring policy の独立した切替境界を明文化していないため、最初の規範的修正はその決定を正確に取り込む要件 revision／必要な後継 ADR の review である。採択前に古い Accepted 文書の意味を書き換えたり、`cc305`／`vt102` の記述だけで仕様を作らない。実装上は `vt101` の選択と `vt102` の direct API・全 consumer が最小範囲となる。`cc305` はそれらの current fit を再レビューしてから再開し、`cc314` の Stage gate は維持する。
3. **争点:** manifest なし保存済み battle に exact な作成時情報が存在しない場合、当時のリビジョンを推測して書き込むことはできない。まず対象件数と不変ソースを read-only で確認し、復元不能な対象が実在する場合のみ、継続不能として明示するか、別途承認した救済・互換方針を設けるかをオーナーに判断してもらう。
4. **今回の非対象:** `CharacterDefinitionV3` の authoring 実装、V2→V3 への資産移行、既存 battle データ変換、実対戦、Stage、production、release/merge の実行は監査から導かれる後続作業であり、本資料はその実行や受入を承認しない。

実利用者が新しい V3 対戦を遊べる状態への実現価値は今回増えていない。将来価値への寄与は、選択・直接 API・旧 battle 継続の具体的な修正箇所と、仕様記録／復元可否の二つの未決ゲートを切り分けたことである。
