## 目的と改訂範囲

最上位の移行・復旧目的は維持する。最初に所有者が Stage で試す対戦は Neva 対 Rio の V3-only とし、移行済み V2 キャラの試合や混在対戦を初回試行の条件にしない。`cc305` はその候補経路と不足のレビュー、`cc314` / `cm314` / `CS_STAGE_TRIAL R2` は所有者が実 Stage 対戦をプレイし、両者の exact V3 revision が battle に固定されたことを確認する到達点に変更した。exact release identity の確定はローカル統合後の `vt104` に残す。

従来 `cc314` に含まれていた V2→V3 移行一件の Stage 使用は、後続 `cc316` / `cm316` / `CS_MIGRATED_STAGE_TRIAL R1` として明示的に保持する。`cc316` は初回試行とローカル移行準備の両方を前提とし、`cc313` 以降の広い評価・本番復旧より前に置く。混在対戦の実装は `cc316` の条件にもせず、移行 V3 の対戦相手は互換性のある V3 とする。既存の本番最終到達点、履歴実績、独立した provider・配備・候補受入・pointer 操作の権限は変更しない。

`cm317` は Neva/Rio のローカル fixture が存在するという限定到達点である。登録、内容受入、Stage 可用性、試合完走は含まない。`cc305` の開始根拠を `cm315`（移行準備）から `cm317` へ変更したため、初回 V3-only 試行を V2 移行経路に依存させない。古い移行経路レビューは履歴として分離し、現行 `cc305` レビューは別記録にした。

## 現状・見積り

2026-09-25 時点で Neva/Rio の候補 fixture はローカルに存在し、`vt102` の不変 V4 binding は部分 WIP。`vt101` の登録・選択、`vt102` の全 consumer と完全対戦、`vt103` の結合、release/Stage/実プレイは未完了である。旧枝と現行枝の ADR-0032 identity は衝突し、WIP の統合可否は別途照合する。Stage の利用者価値はまだ実現していない。

子計画の残計画値は `vt101` 3p、`vt102` 4p、`vt103` 2p、`vt104`–`vt107` 各1pで合計13p。`vt102` は部分 WIP だが完了した point を測定していないため、元の4pから架空の消化量を引いていない。DEV 一名の resource schedule は13pであり、`cc314` の13pはこの roll-up であって追加工数ではない。`cc305` の候補レビューは別に1p。後続 `cc316` の1pは旧 `cc314` の仮見積りを移したもので、実測後に更新する。過去の `cc311`、`cc312`、`cc315` の完了実績は同一日の3pで、`3p/1d` は短いローカル作業からの暫定換算である。Stage、V4 全経路、owner 操作には比較可能な完了実績がなく、条件付き内部日数としてのみ示す。外部承認・配備待ちはその日数に含まない。

PERT の precedence/resource 両計算は残り25p、宣言 velocity では約8.3実働日で、`cc305` の再開を条件とする。2026-09-28（月）から平日一名・祝日と外部待ちを無視して途切れなく進める仮定では、M3の内部作業は10月2日ごろ、最終の内部作業は10月8日ごろ。脆い一日三点標本に対する半速の感度計算（1.5p/日、観測値ではない）では最終内部作業は10月20日ごろになる。これは予測条件を見せる算術で、約束日でも Stage で利用できる日でもない。次に `vt101` または `vt102` が完了して実績が得られた時点で再測定する。

旧 `cc305` work_event は移行経路のレビューに費やした実時刻であり、V3-only レビューの完了または velocity 標本にはしない。`cc305` の suspended 状態を維持し、実行再開はこの改訂とは別の現在適合確認を要する。
