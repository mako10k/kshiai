# ADR-0036: draft の根拠に基づくテスト結果も draft として扱う

- Status: Accepted
- Revision: 1
- Date: 2026-09-16
- Decision owner: Product owner
- Authority: 同名の `.think` が決定の正本。この Markdown は日本語の内容投影。
- Related: [ADR-0034](0034-seal-based-test-authority.md)、`scripts/test-authority.mjs`、`scripts/test-authority.test.mjs`、`verification/character-focused-authoring-request-scope-v1`

## 背景と根拠

受入済み ADR-0034 は、テストを現行の根拠として使うために、検証Seal、正確なソース一致、明示的なCause、staleでない根拠連鎖を要求する。しかしSealまたはCauseが `draft` のとき、テスト結果をどう扱うかは定めていない。現行の選択器はdraftを見ないため、そのテストも `active/current` と表示して合格集計へ含める。2026-09-16の確認時にはactiveな5件中2件の検証Sealがdraftだった。この件数は当時の観測値であり、恒久的な条件ではない。

SealGraphのdraftは暫定的なSealである。ソース一致とstaleなしは、その暫定性を取り除かない。所有者は「draftを根拠とするテスト結果もdraft」と示し、ADR-0034のdraft扱いを明確にするADRの作成を指示した。正確なrevision 1は、2026-09-17に日本語の全レビュー範囲を提示した後に受け入れられた。

## 判断軸と選択肢

目的は、暫定的な検証を確定した合格根拠として表示しないこと。同時に、診断に使えるテストや旧Sealの履歴は失わない。

1. 現状維持：変更は少ないが、draftの結果を `current` と表示し続ける。
2. draftのテストを通常の合格集計から外し、明示的な診断実行は残す：確定結果との混同を小さな変更で防げるが、通常実行の件数は減る。**この案を採用する。**
3. 通常のテスト実行に「確定」と「draft」を併存させて別集計する：draft結果を毎回観測できるが、実行と集計の契約が複雑になる。

## 決定

**D1 — 結果の根拠状態。** 検証Seal自体、または必要な直接・推移的Causeのいずれかがdraftなら、そのテスト結果もdraftの証拠とする。ソースが一致し、staleでなくても、確定した現行の根拠には昇格しない。

**D2 — 選択器と診断実行。** このテストは通常の権威あるpass/fail集計から外し、`draft_basis` という理由で暫定と報告する。明示的な診断コマンドでの実行は可能とし、その成功・失敗も記録済みの正確な根拠に対するdraft結果と表示する。新たな診断コマンドやUIを要求しない。

**D3 — ADR-0034との関係。** Seal欠如、誤ったソース、ソース変更、Cause欠如、staleについてのADR-0034の無効化条件は維持する。それらを単にdraftと呼び替えて有効にはしない。旧Sealは元の根拠についての履歴として保持する。後に確定結果が必要なら、適用される現行・非draftのCause連鎖に照らしてテストを再確認し、新しい非draftの検証Sealを作る。自動昇格はしない。

本ADRはADR-0034のdraft未規定部分を補完し、受入済みADR-0034の決定本文は書き換えない。

## 影響と限界

暫定的なテスト結果を、cc304などの完了や次工程の根拠として誤用しにくくなる。一方、通常集計で実行されるテスト数は減り得る。診断実行の結果は依然として有用だが、確定した合格・不合格を意味しない。この分類はテスト対象の実装が正しいかどうかや、根拠文書の所有者受入の有無を判定しない。draft連鎖を一括で非draftへ変えることも要求しない。

## 互換性・移行

テストファイル、旧Seal、Cause履歴を削除・書換えしない。受入後の実装では、選択器の分類と通常集計からの除外、およびその回帰テストだけを対象とする。これは公開ゲームAPIや保存済みキャラデータを変更しない。

## 検証と権限境界

受入後の実装では、検証Sealがdraftの場合、推移的Causeだけがdraftの場合、非draftの現行連鎖の場合、staleまたはソース不一致の場合を区別して確認する。通常集計にdraft結果が混ざらず、明示的な診断実行では暫定結果と表示されることを確認する。選択器の合格だけでADRの受入や実装の完成とはしない。
