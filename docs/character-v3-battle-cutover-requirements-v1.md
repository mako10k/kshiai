# V3 新規対戦切替と未完了の旧対戦の破棄 — 要件候補 revision 1

- 状態: Proposed（オーナー受入前）
- 日付: 2026-09-28
- 決定者: プロダクトオーナー
- 対象: Kshiai の新規対戦と、V3-only 新規対戦への切替より前に開始され、切替時に未完了の対戦
- 根拠となるオーナー指示: 「V2キャラでの新規戦闘はそもそも廃止」「V2-V3の混在対戦は起きえません」「過去の途中の対戦は『破棄』してください。そのために、余分な実装を使うのは『無駄』です」

## 目的と境界

新しく始める対戦は V3 キャラクター同士に統一する。切替前から途中のまま残る対戦は破棄し、その継続を可能にするためだけの旧版互換処理を作らない。完了済みの過去対戦と、その対戦に記録済みのキャラクター情報は保持する。新しく始めた V3 対戦は、作成時に確定した両者の不変リビジョンで最後まで進める。

「破棄」はこの候補では、切替時点で対象の未完了対戦を保存済み対戦データから削除し、履歴一覧、個別閲覧、再開、再送から参照できなくする意味とする。別の `discarded` 状態や、旧対戦を続けるための新しい reader／補完・移行経路は設けない。削除の具体的な操作、依存データの扱い、件数確認、実行時の回復手順は後続の設計・適用で決める。

## 必須条件

**R1 新規対戦の参加資格。** 切替後の新規対戦は、双方がアクセス可能で対戦に必要な能力を満たす current `CharacterDefinitionV3` の不変 generation を持つ場合だけ開始できる。V2×V2 と V2×V3 の新規作成は、画面・候補検索・random/auto・直接 API のいずれからも成立しない。切替前の実装に V2 作成分岐が残っていることは、これを製品仕様として許可する根拠にならない。

**R2 新規対戦の固定。** 対戦作成時に両者の正確な V3 generation ID、内容同一性、対戦用 snapshot と必要な compiler identity を結合して保存する。作成後の current pointer やキャラクター編集は、その対戦の進行、再送、再読込、表示内容の根拠を変更しない。battle manifest の schemaVersion とキャラクター定義の schemaVersion は別の identity として検証する。

**R3 切替前の未完了対戦の破棄。** V3-only 切替時点で `finished` に達していない、切替前作成の保存済み対戦を対象として破棄する。対象は対戦開始時のキャラクター版や manifest の有無で限定しない。破棄後は履歴一覧、個別閲覧、advance、同一操作の retry/replay からその対戦を継続または復活できない。未完了旧対戦の exact revision を推定・補完して継続することは到達条件ではない。

**R4 完了済み履歴の維持。** 切替前に `finished` に達した対戦は破棄対象に含めず、既存の記録済み世代・snapshot・結果を読み取り可能なまま保持する。過去の結果を V3 の新しい意味に再解釈したり、新しい V3 generation に結び直したりしない。

**R5 切替と観測。** V3-only 新規対戦を利用可能にする前に対象未完了対戦を確定し、破棄結果を読み戻す。新規対戦の V3×V3 成功、V2×V2／混在の拒否、未完了旧対戦の非表示・再開不能、完了済み履歴の可読性をそれぞれ確認する。ローカル試験、Stage、production は別の適用範囲として扱い、それぞれのデータ操作には別途の権限を要する。

## 比較した扱い

- **未完了旧対戦の削除（この候補）:** 破棄の意味が明確で、永続的な旧版継続経路や新しい状態を設けずに済む。一方、データ削除は取り消しにくく、対象確定、関連レコード、実行前後の readback が必要になる。
- **履歴に残して再開だけ禁止:** 対戦記録を残せるが、現行の `active`／`finished` 以外の状態や一覧・個別閲覧・再送の扱いを追加する必要がある。オーナーが不要とした追加実装を生む。
- **旧版のまま継続:** 途中の対戦を失わないが、manifest のない旧対戦まで正確に継続するための reader・復元処理が必要となり、今回の「破棄」の指示に反する。

## 既存権限との関係

- [Accepted ADR-0010](adr/0010-structured-selectable-asset-envelope.md) の不変世代、ready/compatible selection、read-only battle binding と新規対戦における不変 snapshot は維持する。同 ADR の「既存対戦の記録済み legacy manifest を保持する」という方向は、**完了済み**の過去対戦に限って維持し、切替前の**未完了**対戦には今回の後発オーナー指示による破棄条件を適用する。ADR 自体はこの候補だけで改訂・受入済みにならず、必要な後継 ADR で明示的に整合させる。
- [Accepted キャラクター互換要件 revision 6](character-v2-compatibility-requirements-v6.md) の V2→V3 移行、旧 generation bytes の保持、受入済み移行の記録は維持する。同要件の「old battles remain bound/readable」は、今回の新しいオーナー指示によって、切替時点の未完了対戦に対しては破棄へ変更する提案である。旧要件本文を遡及的に書き換えない。
- [Accepted ADR-0030](adr/0030-llm-assisted-character-semantic-migration.think) の V3 authoring policy と、この新規対戦の V3-only 切替は異なる境界である。どちらかの schema 3 だけで他方が完了したと扱わない。V2→V3 キャラクター移行は Neva 対 Rio の初回 V3-only Stage 対戦の前提にしない。
- [cc318 監査](evidence/cc318-v3-battle-cutover-audit-2026-09-28.md)、`cc305`、`cc314`、`vt101`、`vt102` は下流の証拠と計画であり、この要件候補の権限を作らない。監査に記された「manifest なし旧対戦を復元して継続する」検討は、対象未完了対戦については撤回する。完了済み履歴の可読性への実際の影響だけを後続で確認する。

## 非対象と未解決事項

- 対戦途中のデータを今この文書作成時に削除すること、既存の完了済み履歴の削除、V2 キャラクター generation 自体の削除、キャラクター移行、Stage 配備、production 適用は含まない。
- 切替に使う正確な release、実行時点、対象件数、関連レコードの削除・保持、障害時の回復手順は未確定。実データと依存関係を調べ、後続の適用計画で固定する。
- この候補の受入は要件の受入だけを意味する。後継 ADR、設計、実装、テスト結果の受入、対戦データ削除、プッシュ、マージ、配備を自動的には承認しない。
